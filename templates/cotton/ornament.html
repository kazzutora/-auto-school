{% load static %} {% comment %} Ornament, ROSE.md B.6 and B.7. The only way a brush stroke, a heart, a scribble, an arrow, a spark burst or a hand-drawn ring reaches a page: nothing draws one inline, so the norm in B.7 can be counted by grepping for this tag. Always decorative. aria-hidden and pointer-events: none are on the element itself rather than left to the call site, because an ornament that swallows a click on the button underneath it is the one failure mode that never shows up in a screenshot. **Why and not a background image.** B.6 wants the strokes recoloured by class through --brush-a and --brush-b. A background image is a separate document and inherits nothing from the page, so the variables would never arrive; custom properties do inherit across the shadow tree builds, and so does currentColor. That is the whole reason for the indirection. The brushes sit in files of their own and the small marks in one sprite: a section wants one or two strokes and four hearts, so the hearts are worth bundling and a 4 KB stroke nobody asked for is not. Size is not a prop. A stroke is placed by the utility that positions it — .u-brush-edge-top and the rest in app.css — and a heart takes its size from the class the call site passes, the way the icons do. {% endcomment %} {% if kind == 'underline' %} {# The home hero's own strokes, drawn inline so the inner pages share them rather than a lookalike: the tagline's brush under a handwritten line, and the four speed lines.
