# DEV.md — рабочий файл проекта OSK Nawrocki

Читай `tech.md` первым. Подчиняйся ему дословно. Зафиксируй в начале сессии версию ядра из шапки `tech.md` (сейчас **v1**). Версия сменилась — перечитай changelog до того, как писать код.

**Команда: один человек, два режима.** Не смешивай их в одной сессии.

| Режим | Когда | Что делает |
|---|---|---|
| **LEAD** | скелет, контракты, миграции, общие файлы, CI/CD, ревью | часть I этого файла |
| **DEV** | фичи | часть II, одна задача за сессию |

Разделение не бюрократия. Оно физически мешает сессии, которая закрывает фичу, походя переписать общий контракт, чтобы стало удобнее. Контракт меняется только в режиме LEAD, осознанно, с бампом версии в `tech.md`.

## CONTRACT GAP

Не хватает поля, типа, задачи, эндпоинта или пропса компонента — **СТОП**. Код с выдуманным контрактом не пиши.

Выдай блок ровно так:

```
CONTRACT GAP
Что нужно: <поле / тип / задача / эндпоинт>
Зачем: <какой критерий приёмки без него не закрывается>
Предлагаемая форма: <имя, тип, ограничения, дефолт>
Затрагивает: <модели, задачи, шаблоны>
Временная заглушка: <что делаю локально, пока контракт не приедет>
```

Дальше: issue с меткой `contract-change`, работа продолжается на локальной заглушке.

**Обработка в режиме LEAD:**

1. Проверь, правда ли это новый контракт или DEV не нашёл существующий. Второе — отправь к нужному разделу `tech.md`, ничего не меняй.
2. Настоящий пробел: аппендишь определение в соответствующий раздел `tech.md`, **не переписывая существующее**.
3. Бампаешь версию ядра, добавляешь строку в changelog: `v2 — courses.Course: добавлено exam_included (bool, default False)`.
4. Пишешь миграцию, если пробел был в схеме.
5. Закрываешь issue, фиксируешь новую версию ядра.

Никогда не отвечай «сделай как считаешь нужным». Это ровно тот путь, на котором сессии расходятся.

## I.5 Переключение со старого сайта

Отдельный чек-лист на день переезда. Ошибка здесь стоит позиций в поиске.

1. Прогнать `pytest -m redirects` — вся таблица `data/legacy/redirects.csv` зелёная.
2. Снять текущие позиции и список проиндексированных URL из Search Console старого домена.
3. Выкатить прод, проверить `/healthz`, `sitemap.xml`, `robots.txt`.
4. Проверить восстановление из бэкапа вручную.
5. Переключить DNS, дождаться сертификата от Caddy.
6. Проверить руками: `http://` → `https://`, `www` → без `www`, каждый старый URL с пробелом и в percent-encoded виде отдаёт 301 за один шаг.
7. Отправить `sitemap.xml` в Search Console, запросить переиндексацию главных страниц.
8. Прогнать Lighthouse на мобильном: Performance ≥ 90, Accessibility ≥ 95, SEO 100.
9. Неделю следить за 404 в логах Caddy, добавлять недостающие редиректы.

# ЧАСТЬ II — режим DEV

## II.1 Правила режима

1. **Одна задача за сессию.** Один вертикальный слайс, один PR, сфокусированный дифф. Не вываливай всё приложение сразу.
2. **Контракты не выдумывай.** Схема БД, payload задач, имена роутов, пропсы компонентов, контракт `Seo` уже определены. Нет нужного — блок `CONTRACT GAP` в начале файла.
3. **Миграции не пишешь вообще.** Изменил модель по обновлённому `tech.md` — сообщи в режим LEAD.

## II.2 Эталон

Твой слайс повторяет структуру эталонного слайса `apps/gallery`:

```
apps/<feature>/
  models.py        только модели из tech.md §4, ни одного лишнего поля
  admin.py         list_display, list_filter, search_fields, inlines, TranslationAdmin
  forms.py
  views.py         единообразно с эталоном
  urls.py          app_name = "<feature>", имена роутов из tech.md §5
  services.py      чистая доменная логика без ORM, сюда же property-based тесты
  tasks.py         Celery, payload по tech.md §6
  selectors.py     запросы к БД, всегда select_related / prefetch_related
templates/<feature>/
  <page>.html      наследует base.html, использует cotton-компоненты
  _<partial>.html  для HTMX-ответов
tests/
  unit/  contracts/  idempotency/  property/
```

Сверяйся с `apps/gallery`, не изобретай свою раскладку.

## II.3 Чем владеешь и что не трогаешь

**Владеешь целиком:** `apps/courses`, `apps/leads`, `apps/people`, `apps/gallery` (после эталона), `apps/links`, `apps/reviews` и их шаблоны в `templates/<feature>/`.

**Не трогаешь:** `config/**`, `apps/core/**`, `templates/cotton/**`, `templates/base.html`, `templates/layout/**`, `tailwind.config.js`, `static/src/css/app.css`, `scripts/seed.py`, `**/migrations/**`, `.github/**`, `deploy/**`. Сквозная правка — через режим LEAD.

## II.4 Старт запрещён, пока не зелено

Не начинай ни одной задачи, пока чек-лист §I.3 не пройден целиком.

## II.5 Рабочий цикл задачи

```
задача → ветка feat/<scope>-<short-name> → маленькие коммиты по ходу
→ PR с ID задачи в заголовке → CI зелёный → ревью (режим LEAD) → мёрдж → автодеплой
```

Коммиты, PR и комментарии — по конвенции `tech.md` §12: английский, `type(scope): summary`, императив, маленькие логические коммиты по ходу работы, не один в конце.

## S1 — Курсы

### S1.1 Модель курсов, админка, импорт наследия

**Цель.** Наполнить базу всеми 15 курсами школы из выгрузки старого сайта, дать владельцу редактировать их через админку.

**Домен.** `apps/courses`: `Course`, `CourseIntake`, `PriceItem` строго по `tech.md` §4.2.

**Что делаешь.**
- Модели один в один со схемой. Ни одного дополнительного поля.
- `CourseAdmin(TranslationAdmin)`: `list_display = (title, kind, code, price_gross, is_active, order)`, фильтры по `kind`/`is_active`, инлайны `Vehicle` и `CourseIntake`, действие «дублировать курс».
- `scripts/import_legacy.py` (пишет только в свои модели): читает `data/legacy/*.md`, создаёт 15 курсов, применяет таблицу исправления опечаток из `tech.md` §15, помечает два фрагмента `[…]` как требующие ручной доводки.
- `services.py`: `min_start_age(course)` — возраст, с которого можно начать курс (`min_age` минус 3 месяца); `format_price(value, note)`.

**Критерии приёмки.**
- В базе 9 курсов `kind=license` (AM, A1, A2, A, B, B+E, C, C+E, D), 4 `professional` (kwalifikacja wstępna, kwalifikacja wstępna przyspieszona, szkolenia okresowe, ADR), 1 `psychotest`, 1 `operator`.
- Все `slug` совпадают с URL-картой `tech.md` §5.
- Опечатки исходника исправлены, проверяется тестом на конкретных строках.
- Повторный запуск импорта не плодит дубли.

**Тесты.**
- `unit`: импорт создаёт ровно 15 курсов, повторный прогон оставляет 15, каждая из 5 опечаток отсутствует в базе.
- `property` (hypothesis): `min_start_age` для любого `min_age` в 14..30 возвращает значение на 3 месяца меньше и никогда не отрицательное; `format_price` для любого Decimal 0..99999 даёт строку с двумя знаками и `zł`, не роняется на `None`.

### S1.2 Страницы курсов

**Цель.** Каждый курс имеет свою страницу, на которой видно, что даёт, кому подходит, сколько стоит и когда старт.

**Роуты.** `/kursy/`, `/kursy/<slug>/`, `/kierowca-zawodowy/`, `/kierowca-zawodowy/<slug>/`, `/badania-psychologiczne/`, `/wozki-widlowe/`.

**Компоненты.** `<c-course-card>`, `<c-section>`, `<c-heading>`, `<c-badge>`, `<c-price-tile>`, `<c-breadcrumbs>`, `<c-picture>`, `<c-cta-bar>`, `<c-intake-row>`.

**Что делаешь.**
- `selectors.py`: `active_courses(kind)`, `course_by_slug(slug)` с `prefetch_related("intakes", "vehicles")`. Ноль N+1.
- `course_list`: сетка карточек, группировка по `kind`; на карточке код категории, `lead`, цена «от», минимальный возраст, языки.

**Тесты.**

- `unit`: курс без `price_gross` рендерит «Zapytaj o cenę» и не рендерит `0`.

**Компоненты.** `<c-intake-row>`, `<c-select>`, `<c-badge>`, `<c-alert>`.

**Что делаешь.**
- Список `CourseIntake` со `status in (planned, open)` и `start_date >= today`, сортировка по дате.
- Фильтры: курс, язык (`pl/ru/uk`), режим (`stationary/elearning/mixed`). Подмена только строк таблицы через HTMX, шаблон `courses/_intake_rows.html`.

**Критерии приёмки.**
- Прошедшие и закрытые наборы не показываются.
- Пустой результат фильтра даёт человеческий текст с телефоном, а не пустую таблицу.

**Тесты.**
- `unit`: фильтры по каждому измерению и в комбинации; прошедшая дата исключена; `status=closed` исключён.
- `unit`: HTMX-запрос возвращает партиал без `<html>`, обычный — полную страницу.
- `property`: `seats_left` для любых `seats_total`/`seats_taken` не отрицательный; `is_bookable` ложен при нуле мест.

## S3 — Заявки

### S3.1 Форма записи

**Цель.** Рабочая форма заявки. На старом сайте её не было вовсе — это главная поломка, которую чиним.

**Роуты.** `/zapisz-sie/`, `POST /zapisz-sie/submit/`, `/zapisz-sie/dziekujemy/`. Форма встраивается также на `/kontakt/` и на страницу курса.

**Компоненты.** `<c-field>`, `<c-input>`, `<c-select>`, `<c-textarea>`, `<c-checkbox>`, `<c-button>`, `<c-alert>`.

**Что делаешь.**
- `LeadForm`: имя, телефон, email (необязательно), курс (селект, предзаполняется из `?course=` / `?intake=`), язык, сообщение, чекбокс `consent_rodo` (обязательный, с текстом и ссылкой на `/rodo/`), чекбокс `consent_marketing` (необязательный).
- Honeypot-поле `website`, скрытое CSS. Заполнено — лид создаётся со `status=SPAM`, уведомление не отправляется.
- `django-ratelimit`: 5 отправок с одного IP в час.
- IP не сохраняем: `ip_hash = sha256(ip + settings.IP_HASH_SALT)`.
- HTMX-сабмит: успех — партиал с подтверждением на месте формы, ошибки — тот же партиал с подсветкой полей. Без JS форма работает обычным POST с редиректом на `/zapisz-sie/dziekujemy/`.
- После создания лида ставишь в очередь `leads.tasks.notify_owner` и `leads.tasks.send_confirmation` (вторую только если указан email).
- `LeadAdmin`: фильтр по статусу и курсу, поиск по телефону и имени, действие «пометить обработанным», экспорт CSV.

**Критерии приёмки.**
- Форма без `consent_rodo` не создаёт `Lead` и показывает ошибку у чекбокса.
- Успешная отправка создаёт ровно один `Lead` и ставит ровно две задачи (или одну без email).
- Заполненный honeypot даёт видимый успех пользователю, но `Lead.status == SPAM` и ноль уведомлений.
- Сырого IP нет ни в одном поле.
- Форма проходится с клавиатуры, у каждого поля есть `label` и `aria-describedby` на ошибку.

**Тесты.**
- `unit`: валидная отправка → 1 лид, 2 задачи; без согласия → 0 лидов; honeypot → `SPAM`, 0 задач; шестая отправка с того же IP → 429.
- `contracts`: payload обеих задач валиден против `apps.core.contracts`, `FakeMailClient` не падает на валидации.
- `property`: нормализация телефона для входов `+48 605-065-795`, `605065795`, `48605065795` и любых их вариаций даёт один канонический формат.

### S3.2 Уведомления о заявке

**Цель.** Владелец узнаёт о заявке письмом, заявитель получает подтверждение.

**Домен.** `apps/leads/tasks.py`.

**Что делаешь.**
- `notify_owner(lead_id)`: письмо на `SiteSettings.lead_notify_emails` с именем, телефоном, курсом, сообщением и ссылкой в админку. Первым делом проверяет `Lead.notified_at is None`, в конце ставит `notified_at`.
- `send_confirmation(lead_id)`: письмо заявителю на `preferred_language`, шаблоны `leads/email/confirmation_{pl,ru,uk}.html`. Ключ — `confirmed_at`.
- Обе задачи через `MailClient` из `apps/core/clients`, напрямую `send_mail` не зовёшь.
- Ретраи по общим правилам `tech.md` §6. Письмо не ушло после всех попыток — лид остаётся со `status=NEW` и `notified_at=None`, чтобы владелец увидел его в админке.

**Критерии приёмки.**
- Двойной запуск задачи с тем же `lead_id` даёт одно письмо.
- `FakeMailClient(fail_with=500)` вызывает ретрай, лид не теряется, `notified_at` остаётся пустым.
- Язык письма соответствует `preferred_language`, для неизвестного языка — польский.

**Тесты.**
- `idempotency`: каждая задача прогоняется дважды, в outbox один файл.
- `unit` путь ошибки: 500 и таймаут от фейка, проверка числа попыток и состояния лида.
- `contracts`: payload соответствует схеме, лишний ключ отклоняется.

# Тесты: как не написать бесполезные

Ты пишешь тест **из критериев приёмки задачи**, глядя в них, а не в свою реализацию. Проверка себя одним вопросом:

> Если выкинуть мою реализацию и написать её заново с нуля по критериям приёмки, останется ли тест зелёным?

Нет — тест зеркалит код и не проверяет ничего. Перепиши.

Минимум на каждый слайс:

| Тип | Когда обязателен |
|---|---|
| Контрактный на стыке | слайс шлёт payload в Celery или во внешний клиент |
| Идемпотентность | слайс добавляет Celery-задачу |
| Путь ошибки | слайс ходит во внешний клиент, проверяется через `Fake*Client(fail_with=…)` |
| Property-based | слайс содержит чистую логику: расчёты, форматирование, интервалы времени, нормализация |
| SEO + alt | слайс добавляет публичную страницу |
| E2E | слайс лежит на критическом пути «нашёл курс → отправил заявку» |

PR без тестов не проходит гейт. Полная доктрина — `tech.md` §9, Definition of Done — §13.

Если сессия идёт в Claude Code — подключай skill `engineering:testing-strategy`.
