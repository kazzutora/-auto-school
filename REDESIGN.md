**Заменяет `FRONTEND.md` часть A. Ядро v5.**

Причина: заказан другой визуальный язык — тёмный герой с фотографией, мягкий серый фон, крупные скруглённые карточки, две акцентные краски, анимация при скролле. Старый контракт (чёрное/белое/жёлтое, радиус 2px, границы вместо теней, запрет на фото людей) прямо запрещает почти всё из этого списка.

# ЧАСТЬ B — ДИЗАЙН-КОНТРАКТ v5

## B.1 Направление

Тёмная карточка на светлом поле. Страница лежит на тёплом сером фоне, содержимое собрано в крупные скруглённые блоки — часть белых, часть почти чёрных. Фотография работает как материал, а не как украшение: занимает целый блок, а не вставляется в рамочку.

Два акцента с разными ролями. Синий — действие: кнопка записи, отправка формы. Жёлтый — состояние: «набор открыт», подчёркивание слова в заголовке, знак школы. Смешивать роли нельзя: жёлтая кнопка «Zapisz się» и синий бейдж «nabór otwarty» — ошибка.

Знак школы остаётся тем же — чёрный квадрат с жёлтой `L`. Он не переделывается под новый дизайн, наоборот, дизайн строится вокруг него: поэтому жёлтый и остался в палитре, а не заменился оранжевым из референса.

**Чего избегать даже в новом языке:**

- градиентных заливок на кнопках и карточках;
- стеклянного размытия;
- теней с большим радиусом, дающих «плавающий» вид;
- третьего акцентного цвета;
- фотографий людей, подписанных как сотрудники школы, если это не сотрудники;
- анимации ради анимации: вылетов сбоку, параллакса, счётчиков там, где нет чисел.

## B.2 Палитра

```js
// tailwind.config.js — светлая тема
paper:   { DEFAULT: "#E9E8E4", 50: "#F2F1EE", 100: "#DEDDD8" }  // фон страницы
surface: { DEFAULT: "#FFFFFF", muted: "#F7F6F3" }               // белые карточки
ink:     { DEFAULT: "#1B1B20", 800: "#26262C", 700: "#3A3A44",
           500: "#6B6B78", 300: "#9C9CA8" }                     // тёмные карточки и текст
primary: { DEFAULT: "#3F3AE6", 600: "#332EDB", 100: "#E4E3FC" } // действие
accent:  { DEFAULT: "#FFD400", 600: "#E5BE00", 100: "#FFF6CC" } // состояние
state:   { ok: "#1E7A56", warn: "#B27C00", err: "#C0392B" }
line:    { DEFAULT: "#D7D6D1", dark: "#33333C" }
```

Тёмная тема — перестановка ролей, не инверсия:

```js
paper:   #121216 / 50:#17171C / 100:#1D1D23
surface: #1B1B20 / muted:#222229
ink:     #F2F1EE / 800:#E2E1DC / 700:#C4C3BE / 500:#8E8E99 / 300:#63636E
primary: #6C68F0   // светлее, чтобы держать контраст на тёмном
accent:  #FFD400 / 100:#2C2814   // сам жёлтый без изменений; бледный тон темнеет, как у primary (tech.md v27)
line:    #2E2E37 / dark:#3C3C47
```

**Контраст проверяется, а не прикидывается:**

- текст к фону минимум 4.5:1, крупный минимум 3:1;
- белый на синем `#FFFFFF`/`#3F3AE6` = 7.4:1, это основная пара кнопки;
- **на жёлтом только почти-чёрный текст**, белый даёт 1.6:1 и запрещён;
- на тёмной карточке основной текст `ink.800`, вторичный `ink.500` из тёмной темы.

## B.3 Типографика

Три семейства, все самохостом в `static/fonts/`, формат woff2, `font-display: swap`.

| Роль | Шрифт | Начертания | Где |
|---|---|---|---|
| Дисплей | **Archivo Expanded** | 700, 800 | h1, h2, названия групп, числа-акценты |
| Текст | **Manrope** | 400, 500, 700 | абзацы, кнопки, поля, карточки |

Archivo остаётся, потому что на нём построен знак школы — иначе логотип отвалится от сайта. Manrope заменяет Public Sans: он геометричнее и ближе к тому, что на референсе, и полностью поддерживает польскую диакритику.

# ЧАСТЬ C — АНИМАЦИЯ

## C.1 Принцип

Анимация подсказывает, что произошло и что можно нажать. Она не развлекает. Каждое движение либо отвечает на действие пользователя, либо помогает заметить появившийся блок.

## C.2 Чем делать

**Никакой библиотеки анимации.** Ни GSAP, ни Motion, ни AOS.

Причина считается, а не берётся на веру: htmx около 14 КБ gzip плюс Alpine около 15 КБ уже съедают почти весь бюджет JS. GSAP добавит 27.8 КБ, Motion — 45.6 КБ. Это удвоение веса скриптов ради того, что платформа теперь умеет сама.

Работаем на трёх вещах:

1. **CSS scroll-driven animations** (`animation-timeline: view()`) — появление блоков при скролле. Поддержка около 87% глобально: Chrome и Edge с 115, Safari с 26, Firefox с 158. Оборачивается в `@supports`, где не поддерживается — блок просто виден сразу. Это не деградация, это отсутствие украшения.
2. **CSS transitions** — состояния кнопок, карточек, полей.
3. **Alpine** — то, что уже есть: табы, аккордеон, мобильное меню, карусель.

Собственного JS для анимации — меньше 3 КБ: счётчики чисел и перелистывание карусели.

## C.3 Список движений

| Что | Как | Длительность |
|---|---|---|
| Появление секции при скролле | opacity 0→1, translateY 16px→0, `animation-timeline: view()`, `animation-range: entry 10% cover 30%` | по скроллу |
| Заголовок героя | три строки со сдвигом 60ms, opacity + translateY 20px, один раз при загрузке | 500ms |
| Кнопка hover | фон и тень | 160ms |
| Карточка hover | тень + translateY -2px | 180ms |
| Ссылка-стрелка | translateX 4px | 160ms |
| Шапка при скролле | высота 76→64px, появление границы | 200ms |
| Табы | индикатор transform | 220ms |
| Аккордеон | `grid-template-rows` 0fr→1fr | 260ms |
| Счётчики зданности | count-up при входе в экран, IntersectionObserver | 900ms |
| Карусель | `scroll-snap` + `scroll-behavior: smooth` | нативно |
| Переход между страницами | `@view-transition { navigation: auto }` | нативно, где есть |
| Мобильное меню | translateX -100%→0 | 240ms |

Кривая одна на весь сайт: `cubic-bezier(.22,.61,.36,1)`. Пружин, отскоков и `ease-in-out` вперемешку нет.

## C.4 Чего не делать

- параллакса фона;
- вылетов сбоку и снизу больше чем на 16px;
- анимации букв по одной;
- бесконечных пульсаций и «дышащих» кнопок;
- курсора-кружка, следящего за мышью;
- прелоадера с процентами — страница должна открываться, а не грузиться;
- повторного проигрывания появления при каждом скролле вверх-вниз.

## C.5 Доступность

Весь блок движений оборачивается:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Счётчики при этом сразу показывают итоговое число, а не остаются на нуле. Это проверяется тестом.

## D.2 Правило, которое нельзя нарушать

**Стоковая фотография человека не может быть подписана как сотрудник или ученик школы.** Карточка инструктора со стоковым портретом и подписью «Piotr, instruktor od 8 lat» — это выдуманный человек на коммерческом сайте. Это подделка, а не дизайн, и на неё легко нарваться: клиент придёт в школу и не найдёт того инструктора.

Отсюда:

- герой, фоны, абстрактные сцены — сток допустим;
- инструкторы, машины школы, плац, классы — **только реальные снимки**, иначе блок не рендерится и показывает `<c-empty>`;
- в демо для владельца стоковые фото помечаются водяным знаком `ZDJĘCIE POGLĄDOWE` и об этом пишется в письме.

## D.5 Скрипт загрузки

Кладётся в `scripts/fetch_photos.sh`, запускается вручную. Ссылки подставляются те, что выбрал человек глазами — автоматический подбор картинок даёт случайный результат.

```bash
#!/usr/bin/env bash
set -euo pipefail
DEST="static/img/source"
mkdir -p "$DEST"

# формат: имя_файла|прямая_ссылка|источник_для_credits
while IFS='|' read -r name url source; do
  [[ -z "${name:-}" || "$name" == \#* ]] && continue
  echo "→ $name"
  curl -fsSL "$url" -o "$DEST/$name"
  echo "$name|$source" >> "$DEST/CREDITS.txt"
done < scripts/photos.txt

echo "готово. дальше: make optimize-photos"
```

`scripts/photos.txt` — список, который заполняет человек. `CREDITS.txt` кладётся в репозиторий и на страницу политики: даже там, где атрибуция не обязательна, знать происхождение файла нужно.

## D.6 Обработка

```
исходник → обрезка под нужное соотношение → AVIF + WebP + JPEG-фоллбэк
размеры: 480 / 960 / 1440 / 1920
герой ≤ 180 КБ, карточки ≤ 90 КБ, портреты ≤ 60 КБ
```
